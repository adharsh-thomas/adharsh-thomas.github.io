Edge AI · Prototype

Adaptive video inference

Running a detector on every frame spends compute even when a scene barely changes. I’m prototyping a scheduler that uses recent frames and caps how long a region can go without a fresh detection.

What I’m measuring

Detector calls, end-to-end latency, and missed detections against a detector-on-every-frame baseline.

How I test ideas

What I look for when an architecture has to work within a shared compute, memory, or power budget.

Start with a baseline

For video, that means running the same detector on every frame. For image reconstruction, a simple resize provides a reference for what the learned model adds.

Change one part of the system

Keep the detector fixed when testing a scheduler. In a model experiment, compare against a simpler variant to see what attention or another added component contributes.

Measure the trade-off

Track latency and detector calls alongside missed detections. Inspect hard cases such as motion and scene changes, where reusing an older prediction can cause errors.
